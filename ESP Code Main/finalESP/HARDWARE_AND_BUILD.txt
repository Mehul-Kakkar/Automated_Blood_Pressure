Hardware findings and build/provisioning notes

Pin map derived from checked-in sketches:
- Microphone ADC: GPIO4 (`korotkoffDebug.ino`), 2 kHz sampling. Existing HP/LP coefficients and event thresholds are retained.
- HX710B OUT/SCK: GPIO8/GPIO9 (`pumpvalveTest.ino`); the main firmware uses the installed `hx710b_arduino` library and exposes the supplied rough mmHg estimate as estimate-only.
- L298N pump IN1/IN2/EN: GPIO5/GPIO4/GPIO15 (`pumpvalveTest.ino`). Microphone input is GPIO10; pump IN2 on GPIO4 is configured as an output.
- L298N valve IN1/IN2/EN: GPIO6/GPIO7/GPIO16 (`pumpvalveTest.ino`). The operator confirmed the valve is normally open: firmware energizes it closed during inflation, then cuts valve power at the 130 mmHg ceiling to open it and release pressure.

The pressure conversion uses the operator's gauge-checked rough calibration: `(signed_raw_counts - 1000000) / 2670000` PSI, converted to mmHg. Thus 6.34 million counts is about 2 PSI (103 mmHg). Inflation is pressure controlled with a 130 mmHg ceiling. At the ceiling the firmware stops the pump before deenergizing the valve. A 120-second pump runtime timeout also stops the pump and opens the valve. Pressure is still reported as an estimate.

Dependencies: Arduino-ESP32 core 3.x, PubSubClient 2.8.x, ArduinoJson 6.21.x. Compile/upload the `finalESP.ino` sketch folder for the exact ESP32-S3 board selected in Arduino IDE/CLI. The separate `DisplayCode/finalDisplay/finalDisplay.ino` needs Arduino-ESP32 core 3.x and ArduinoJson 6.21.x. Match the configured ESP-NOW channel on both boards and the Wi-Fi AP.

For MQTT, copy `secrets.example.h` to local `secrets.h` (the latter is git-ignored), then set the actual Wi-Fi SSID/password, enrolled device UUID, per-device MQTT username/password, broker hostname/port, and trusted broker CA PEM. Never use plaintext MQTT or a skip-verification TLS mode. The broker must ACL the device principal to publish only its own telemetry/status/responses and subscribe only to its own commands topic. Firmware subscribes/publishes the backend's bp/v1/devices/{device_id}/{commands,telemetry,status,responses} topics.

This folder contains firmware/configuration only. It cannot create a backend session for a touchscreen START because the current backend schema/service has no device-originated session-request message. The display START therefore needs a backend session_id or is rejected. Backend enrollment/provisioning, frontend synchronization, and backend tests remain in the backend/frontend project scope and were not edited under the folder-only constraint.
